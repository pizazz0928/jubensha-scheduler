# 备份与恢复说明

正式数据保存在 MySQL 的 `scheduler_state` 表。建议同时使用腾讯云数据库自动备份和应用校验备份。

## 备份策略

1. 开启腾讯云 MySQL 自动备份，保留周期至少 14 天。
2. 每周导出一次应用校验备份，下载到独立设备保存。
3. 每次发布、批量修改资料和恢复数据前额外导出一次。
4. 每季度在测试数据库做一次恢复演练。

## 导出应用备份

最简单的方法是使用管理员账号进入“记录统计”，点击“下载完整备份”。浏览器会下载带完整性校验的 JSON 文件。

也可以通过命令行导出。运行命令的电脑需要能连接正式 MySQL。先设置 `CONNECTION_URI`，或设置完整的 `DB_` 变量。

Linux：

```bash
export CONNECTION_URI='mysql://账号:密码@地址:3306/数据库名'
pnpm backup:export
```

Windows PowerShell：

```powershell
$env:CONNECTION_URI="mysql://账号:密码@地址:3306/数据库名"
pnpm backup:export
```

默认文件写入 `backups` 目录。也可以指定路径：

```bash
pnpm backup:export /安全目录/jubensha-before-release.json
```

命令会显示数据版本和 SHA256 校验值。备份内容含基础资料、场次、玩家名单和操作记录，不含登录密码、会话密钥或数据库密码。

## 恢复前准备

1. 通知使用者暂停操作并关闭其他浏览器页面。
2. 导出一份恢复前备份。
3. 确认目标数据库和备份文件日期。
4. 在腾讯云控制台临时停止公网访问，或选择没有营业操作的时间窗口。

## 执行恢复

管理员可以进入“记录统计”，点击“恢复备份”，选择 JSON 文件，并按提示输入“恢复全部数据”。成功后页面会自动重新载入。

命令行恢复必须包含 `--confirm`：

```bash
pnpm backup:restore /安全目录/jubensha-backup.json --confirm
```

恢复工具会先验证文件格式、数据版本和 SHA256 校验值。任何校验失败都会停止操作。成功恢复后数据库版本会递增，恢复事件会写入操作记录。

## 恢复后验收

1. 访问 `/healthz`，确认状态为 200 且存储类型为 `mysql`。
2. 登录并核对 DM、剧本、房间、最近场次和玩家名单。
3. 查看操作记录顶部的数据恢复事件。
4. 创建一个测试场次，刷新页面确认存在，再删除或取消测试场次。
5. 重启服务，再次确认恢复后的资料存在。
6. 恢复公网访问。

## 腾讯云数据库恢复

应用备份无法使用时，可以在腾讯云 MySQL 控制台按时间点恢复到新实例。先把 CloudBase Run 的数据库环境变量指向新实例，再检查 `/healthz` 和业务数据。确认无误后保留旧实例一段时间，随后按门店的数据保留制度处理。

## 安全要求

- 备份文件可能包含玩家昵称、电话和门店运营信息，应存放在受控目录。
- 不要把备份文件提交到 GitHub。项目已忽略 `backups` 目录。
- 不要在聊天、截图或工单中公开数据库连接串。
- 删除旧备份前，先确认至少有一份近期备份和一份可用的云数据库备份。
